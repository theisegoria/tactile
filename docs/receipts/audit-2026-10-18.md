# Correctness audit and Tactile Lab — 18 October 2026

This audit extends the September receipt; it does not replace its historical results. The baseline built successfully and passed 108 tests. Additional malformed-input probes reproduced crashes and a recording deadline overrun before implementation. Work was performed in the primary agent, with no delegation.

## Confirmed defects and repairs

| Area | Reproduction / failure | Repair and regression coverage |
|---|---|---|
| Audio formats | Non-finite/unsupported rates, channel counts and frame durations reached conversions or AudioToolbox. A stereo buffer containing 959 samples crashed. | Validate before system calls and conversions; validate whole interleaved frames before encoder mutation. `AudioValidationTests` checks rejection and preserved pending audio. |
| Descriptor parsing | Oversized report size/count multiplication and accumulation could overflow. | Checked arithmetic produces a parse error. `MalformedInputTests` covers malformed descriptors. |
| Extraction and scanning | Offsets inferred from longer reports indexed shorter reports and trailer bytes. | Validate each report's actual payload boundaries; invalid extraction returns nil. Mixed-length regressions cover scanner and extractor. |
| Speaker framing | Partial headers, prefix limits and CRC layout could index or allocate invalid reports. Oversized drops skipped playback time. | Validate full layout and distinguish framing failure from oversize; preserve dropped-frame cadence. Core/audio regressions exercise one/two-byte lengths and malformed layouts. |
| Microphone deadlines | A 40 ms recording waited roughly 261 ms for its stream to finish; silent streams could wait indefinitely. | Independent bounded stream deadlines finish/cancel the forwarder on timeout and cancellation. Silent scan/record tests and cancellation regressions pass. |
| Manager lifecycle | Finishing event continuations under the manager lock re-entered termination callbacks; shutdown/restart and late opens crossed generations. | Finish outside the lock; generation fences and cleanup barriers; injectable discovery/transport. Lifecycle tests run without hardware. |
| Reconnect and snapshots | `firstController` ignored reconnection; old input tasks could clear a new controller snapshot. | Accept reconnected events and fence snapshot lifetime by generation. |
| Pump lifecycle | Overlapping starts/stops could let a replacement pump overlap the prior submit callback. | Join prior runs and handle self-stop/restart safely. Concurrent stress and blocked-submit restart tests pass. |
| Bluetooth feature CRC | The old fallback accepted any bad CRC. This contradicts the September audit's refuted classification. | Accept only explicitly supported stripped-CRC lengths for known feature reports; reject corrupted complete framing. |
| C handles and callbacks | Retained handles and in-flight callbacks needed teardown fencing. | Context shutdown invalidates handles, drains callback work and prevents late snapshot updates; focused lifetime regressions pass without devices. C ABI layout/symbol checks remain unchanged. |
| Binding/CLI validation | Out-of-range arguments could truncate or reach discovery before errors. | Python/Unity argument guards and CLI early validation. Python player-LED mask correctly permits the documented instant bit (0x20). |
| Neutral output | LEDs and experimental audio routing/levels could remain app-owned after Stop All. | Neutralization resets the complete app-owned output state; a focused regression verifies the resulting fields. |
| GameController observers | NotificationCenter retained block observers after their bridge was released. | Explicit token ownership removes observations on teardown; a private-center regression proves callbacks stop after release. |
| App selection and history | Paused raw reports and observations could retain data from a previous controller. | Clear the paused display and snapshot selection on device changes; archive observations with their original device identity. Simulation snapshots are bounded to 20. |
| Native text accessibility | Controller identity changed visually while macOS retained the selectable text wrapper's old accessibility value. | Recreate the wrapper when selected identity changes. This final adjustment builds but its UI rerun remains pending after the owner stopped desktop automation. |
| Packaging | Universal framework builds left the shared host output as the last architecture built. | Separate scratch paths for each architecture preserve the host build. Universal packaging reverified. |

## Final static-only pass and revised scope

The owner stopped desktop automation, then requested static analysis and patches followed by a push to GitHub. The running UI test runner, its xcodebuild process and its simulated app were terminated, and their exit was verified. No further app interaction or automated tests were run. The following additional paths were reviewed and patched by inspection:

- **Pending microphone permission:** accepting a system permission prompt after Stop All could start a new effect because the view checked only device identity. The session now owns that pending request, checks cancellation before and after permission, and invalidates it on Stop All, selection changes or a newer output request. Cleanup does not wait for the system prompt to be answered.
- **Discovery cancellation:** cancellation of the settle sleep threw before the unstructured collector was canceled. A defer now cancels the collector on every exit path.
- **Diagnostics cancellation:** the detached collection task previously outlived cancellation of its caller. Cancellation now propagates to it, with checks before starting work and after the firmware read.
- **Encoder error recovery:** an earlier converter error can leave more than one complete frame queued. Flush now drains complete frames before padding the remainder, preventing a negative padding count.
- **Mixed-session reports:** each Markdown operation now states whether it was simulated or physical, independently of the current session mode.

Swift frontend syntax parsing and `git diff --check` passed for these changes. They have **not** received a subsequent build, runtime regression run or hardware check. The most recent signed archive (`build/lab-release.wRL2AR/Tactile Lab.xcarchive`) passed signature/runtime/architecture checks before these final static patches; it is not an archive of the final pushed source.

Notarization, stapling, ready-to-share ZIP/DMG delivery and remaining visual checks are deferred. The `tactile` Keychain notarization profile was absent at the last check. Marketing copy already exists in the owner's Notes note titled “Tactile Lab — marketing copy & screenshots”; no further Notes interaction was performed after the desktop automation restriction.

## GitHub compatibility follow-up

The normal push-triggered [CI run for b89f8ed](https://github.com/theisegoria/tactile/actions/runs/39096743799) failed during the Xcode 16.4 library build: that compiler inferred `any Error` for the default transport test-double closure and could not resolve `.notSupported`. The closure now explicitly declares its `TransportError` throw type. No deployment target, public API or CI gate was relaxed. The follow-up has syntax-only local validation; its remote CI result must be checked separately.

The [30532cd run](https://github.com/theisegoria/tactile/actions/runs/39096872387) passed the warnings-as-errors build, then reported four timing failures. Static inspection found that tests ran blocking C callback drains, synchronous teardown and stalled pump joins on Swift's cooperative executor; those workers are also needed to resume the test timers and release tasks. These blocking test operations now use dedicated threads. The silent-stream 250 ms limits, callback lifetime assertions and pump overlap checks are unchanged. This repair is pending the next normal push-triggered CI result; no local test or app was launched.
